# Competitor analysis

| Baseline | Already does | BlastPath must demonstrate beyond it |
|---|---|---|
| Dependabot/GitHub dependency graph | direct/transitive dependencies, alerts, SBOM/update flows | cross-repo incident window evidence and exact containment replay |
| OSV-Scanner | scans lockfiles/SBOMs for known vulnerabilities/malware | organization-wide path explanation plus build proof |
| GUAC | graph supply-chain metadata, transitive paths, response/patch use cases | sharply usable six-minute command workflow and honest temporal classifications |
| Likely hackathon graph visualizer | impressive node-link picture | deterministic operational answer, raw evidence, path cut |
| Likely LLM security chat | conversational polish | reproducible non-hallucinated graph results |

## Defensible wedge

BlastPath does not compete on discovering the advisory or drawing the largest graph. It competes on the time-critical decision after disclosure: which services have a path, which builds prove in-window use, what remains unknown, and which shared dependency action removes the most observed paths.

## Demo order implication

Lead with two differing evidence classifications, reveal the real HydraDB query/path, and then collapse both paths with one simulation. Do not spend demo time on upload forms, chat, raw package lists, or graph animation.
